# 面向领导的 AI 知识 Deep Research Agent —— 分析与规划

> 目标：基于 **openJiuwen**，复用 **agent-core / agent-runtime / deepsearch**，打造具备 Deep Research 能力的 Agent，帮助领导**深度理解 AI 知识**与**面上科研**（战略层、总览层、可决策层），而非论文级细枝末节。

---

## 1. 问题定义

### 1.1 要解决什么

领导需要的不是「再写一篇综述」，而是：

| 领导问法 | Agent 应交付的形态 |
|---------|-------------------|
| AI 现在到哪一步了？ | 技术成熟度地图 + 可信度标注 |
| 我们该投什么方向？ | 机会窗口 / 风险 / 竞品与政策约束 |
| 某领域论文/项目在说什么？ | 3 层摘要：一句话 → 一页简报 → 证据链 |
| 面上科研怎么布局？ | 问题树、关键路径、资源与人才缺口 |

**「面上科研」在本项目中的含义（建议统一口径）：**

1. **面向上层决策的科研认知**：趋势、格局、瓶颈、可落地路径  
2. **可映射到基金/规划语境**：如国家/院所「面上」级课题的问题提出、研究意义、技术路线与预期成果表述  
3. **刻意控制深度**：默认到「能拍板」，按需下钻到「能答辩」

### 1.2 非目标（刻意不做）

- 替代领域专家做最终学术判断  
- 无引用、无出处的「自信胡编」  
- 一次对话输出几十页无人读的长文  
- 与具体业务系统深度耦合（第一期保持可独立运行）

### 1.3 成功标准（可验收）

- 一次典型问题（如「多模态大模型在医疗影像的机会与风险」）能在可接受时延内产出：**领导简报 + 证据清单 + 后续追问入口**  
- 每条关键结论可回溯到检索来源（论文 / 报告 / 政策 / 网页）  
- 支持多轮「收窄 / 加深 / 对比 / 改写成汇报口径」  
- 架构上可见地复用 openJiuwen 的 core / runtime / deepsearch，而不是另起炉灶

## 2. openJiuwen 能力复用分析

> 以下按常见 openJiuwen 模块职责做**复用映射**。落地前应用仓库 README / 示例确认包名与 API；若命名略有差异，以官方为准，映射关系不变。

### 2.1 agent-core —— Agent 的「骨架」

**适合复用：**

- Agent / Skill / Tool 抽象与注册  
- 会话状态、记忆（短期对话记忆 + 可选长期摘要）  
- Prompt / System Policy 管理  
- 工具调用协议（搜索、读页、结构化输出）

**本项目落点：**

- 定义 `LeadershipDeepResearchAgent`（或等价 Skill 组合）  
- 内置领导场景 System Prompt（口径、禁忌、输出结构）  
- 注册工具：DeepSearch、文献解析、简报渲染、对比表生成等

### 2.2 agent-runtime —— Agent 的「发动机」

**适合复用：**

- 多步规划与执行循环（plan → act → observe → revise）  
- 超时、重试、并发工具调用  
- 中间产物落盘 / 流式输出  
- 任务编排（子任务、检查点）

**本项目落点：**

- Deep Research 工作流作为 Runtime 上的 **长任务**：可暂停、可续跑、可展示阶段进度  
- 阶段化：澄清意图 → 广搜 → 精读 → 交叉验证 → 成稿 → 领导改写

### 2.3 deepsearch —— Agent 的「眼睛」

**适合复用：**

- 多跳检索、查询改写、结果去重与排序  
- 网页 / 文档抓取与摘要  
- 与 Agent 工具接口的对接方式

**本项目落点：**

- 作为默认「外部世界入口」  
- 在其上叠加**领导场景检索策略**（见第 4 节）：来源分层、中英混合、政策/产业/学术三分法

### 2.4 复用边界（避免重复造轮子）

| 自己实现 | 直接复用 openJiuwen |
|---------|---------------------|
| 领导简报 Schema / 模板 | Agent 生命周期、工具协议 |
| 科研「面上」问题树与口径改写 | Runtime 多步执行 |
| 证据分级与可信度规则 | DeepSearch 检索与抓取 |
| 领域词表 / 评测集（AI 领导场景） | 会话与记忆基础设施 |

## 3. 产品形态（给谁用、怎么用）

### 3.1 用户画像

- **一级用户：领导 / 决策者** —— 要短、要结论、要风险、要下一步  
- **二级用户：秘书 / 战略研究岗** —— 要可编辑稿、要出处、要对比表  
- **三级用户：技术顾问** —— 要可下钻证据链、要方法与局限

### 3.2 交互形态（建议 MVP）

1. **对话入口**：自然语言提问 + 可选「汇报模式 / 学习模式 / 立项模式」  
2. **过程可视**：展示 Research 阶段进度（检索中 / 精读中 / 交叉验证 / 成稿）  
3. **结构化产出**（固定章节，便于复印进 PPT）：
   - 一句话结论  
   - 背景与为何现在重要  
   - 技术/产业/政策三棱镜  
   - 关键判断（带置信度）  
   - 风险与误区  
   - 建议动作（30 天 / 90 天）  
   - 附录：来源与术语表  

### 3.3 三种预设模式

| 模式 | 目标 | 输出偏重 |
|------|------|----------|
| 汇报模式 | 开会用 | 1 页简报 + 3 条建议 + 风险 |
| 学习模式 | 补齐认知 | 概念阶梯 + 类比 + 必读清单 |
| 立项/面上模式 | 写意义与路线 | 问题提出 → 意义 → 路线 → 指标 → 风险 |

## 4. Deep Research 工作流设计

```
用户问题
   │
   ▼
① 意图澄清（领导场景槽位填充）
   - 决策场景？学习？立项？
   - 时间范围、地域、行业约束
   - 深度：简报 / 标准 / 深潜
   │
   ▼
② 查询规划（Query Plan）
   - 分解子问题（技术 / 产业 / 政策 / 竞品 / 风险）
   - 生成多组检索词（中英、同义改写）
   │
   ▼
③ DeepSearch 广搜（复用 deepsearch）
   - 并行检索 → 去重 → 权威度初排
   │
   ▼
④ 来源分层与配额
   - A 学术（顶会/顶刊/综述）
   - B 产业（厂商/咨询/开源生态）
   - C 政策与标准
   - 每层保底条数，避免单一信源偏见
   │
   ▼
⑤ 精读与抽取
   - 主张 / 证据 / 反证 / 适用边界
   │
   ▼
⑥ 交叉验证与冲突处理
   - 标注「共识 / 争议 / 未知」
   │
   ▼
⑦ 成稿 + 口径改写
   - 领导简报 Schema 填充
   - 可选：面上项目表述改写
   │
   ▼
⑧ 多轮修订
   - 「更短」「更偏产业」「对比 A vs B」「改成汇报口播」
```

### 4.1 领导场景槽位（Intent Schema）

建议强制结构化（可由 Agent 追问补齐）：

- `goal`: brief | learn | proposal  
- `topic`: 主题  
- `horizon`: 近 6 个月 / 1–3 年 / 5 年+  
- `audience`: 厅局级 / 院所领导 / 企业高管（影响用词）  
- `constraints`: 行业、国别、预算敏感度  
- `depth`: L1 简报 / L2 标准 / L3 深潜  

### 4.2 证据与置信度规则（防幻觉）

- 无来源不得写「事实断言」；允许写「待验证假设」并显式标注  
- 置信度：`高`（多独立来源一致）/ `中`（少数来源或二手）/ `低`（推测）  
- 冲突必须呈现，不得静默择一

## 7. 实施路线图

### Phase 0 —— 环境与复用摸底（0.5–1 天）

- 获取并安装 openJiuwen（含 agent-core / agent-runtime / deepsearch）  
- 跑通官方 DeepSearch / Agent 最小示例  
- 输出《API 对照表》：我们要用的类、配置项、限制（并发、超时、配额）

### Phase 1 —— MVP：可出领导简报（3–5 天）

- 固定 Intent Schema + 三模式 System Prompt  
- Runtime 跑通 ①澄清 → ③广搜 → ⑤抽取 → ⑦成稿  
- 输出 Markdown 简报（含来源列表）  
- 5 条黄金问题手工验收  

### Phase 2 —— Deep Research 强化（1 周）

- 来源分层配额、冲突标注、置信度  
- 精读预算（最多 N 篇深读）与阶段性流式进度  
- 「面上/立项」改写模板  
- 简单 Web 或 CLI 进度展示  

### Phase 3 —— 可用性与可信（持续）

- 评测集扩展（医疗 AI、具身智能、智算、安全对齐等领导常问域）  
- 引用格式规范化、导出 PPT 大纲  
- 可选：对接内部知识库（若有）作为第四信源层

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| DeepSearch 结果噪声大 | 简报误导 | 权威源白名单 + 分层配额 + 冲突展示 |
| 模型幻觉 | 领导信任崩塌 | 强制引用；无证据标「未知」 |
| 时延过长 | 体验差 | 先出 L1 快报，后台继续 L2；可配置深度 |
| 上游 API 变动 | 改造成本 | 业务层只依赖薄适配器 |
| 「面上」口径歧义 | 产品对不齐 | 本文件第 1.1 节统一；产品评审确认 |
