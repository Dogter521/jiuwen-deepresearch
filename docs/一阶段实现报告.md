## 1. 本阶段目标与结论

规划要求第一阶段做到：锁定上游版本、打通「澄清 → 检索 → 抽取 → 成稿」、输出带来源结构的 Markdown 简报，并用 5 条黄金问题验收。MVP **不上** agent-runtime，本地 CLI 即可。

**结论：结构已经跑通。** 本仓库完成了领导场景的薄业务层（意图槽位、三套模板、证据口径、CLI）。默认 `dry-run` 不调用模型与搜索，用于验收流程；接入真实研报时再提供大模型与搜索 API。

## 3. 实现架构

```
用户问题
   │
   ▼
parse_intent（目标 / 深度 / 读者 / 时间范围）
   │
   ▼
compose_research_query + 选择模板
   │
   ├─ engine=dry-run     → 按模板填结构稿（无事实断言）
   └─ engine=deepsearch  → AgentFactory.run(report_template=...)
   │
   ▼
render_brief → output/*.md
```

原则不变：业务逻辑在本仓库；检索与多步研究交给 DeepSearch；执行引擎在 agent-core 内，不把 agent-runtime 当发动机。

核心模块：

- `intent.py`：从问句推断 brief / learn / proposal，以及 L1–L3、时间范围
- `templates.py`：加载对应 Markdown 模板
- `engines/dry_run.py`：离线占位引擎
- `engines/deepsearch.py`：封装 `Config`、`AgentFactory`、`parse_endnode_content`；每次新 `conversation_id`
- `workflow.py`：编排并落盘
- `cli.py`：命令行入口

## 4. 三种模式（模板章节）

| 模式 | 参数 | 章节重点 |
|------|------|----------|
| 汇报 | `--mode brief` | 一句话结论、三棱镜、关键判断、风险、30/90 天动作 |
| 学习 | `--mode learn` | 类比、易混概念、能力边界、必读清单 |
| 立项 | `--mode proposal` | 问题提出、意义、路线、指标、可行性 |

模板一级/二级标题带「功能概述」「是否核心章节」，以便直接交给 DeepSearch 的 `report_template`。

## 5. 如何运行与验收

环境：Python 3.11 或 3.12（不要用 3.14）。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest -q
jiuwen-research "多模态大模型在医疗影像的机会与风险" --mode brief
```

本阶段离线验收结果（2026-08-24）：

- `pytest`：6 passed
- 汇报 / 学习 / 立项各跑通一条，简报写入 `output/`

黄金问题：

1. 多模态大模型在医疗影像的机会与风险（brief）
2. 具身智能现在到哪一步了，院所该不该布局（brief）
3. 给非技术领导讲清楚什么是 Deep Research Agent（learn）
4. 面向国家自然科学基金面上项目，AI 安全对齐可以怎样提问题（proposal）
5. 智算基础设施投入的决策要点：建设、租赁还是联合（brief）

## 6. API 与密钥（本阶段边界）

**不需要本仓库对外提供 HTTP API。** MVP 是本地 CLI。

**dry-run 不需要任何外部密钥。**

要生成带出处的真实简报，使用方自行配置两类 **外部** API（写入本地 `.env`，不要提交仓库）：

1. 大模型：`LLM_BASE_URL` + `LLM_API_KEY`（OpenAI 兼容；推荐 Qwen3-Max 等官方已验证模型）
2. 搜索：`SEARCH_ENGINE_NAME` + `SEARCH_API_KEY`（如 Jina，国内可用 `https://s.jinaai.cn`）

```bash
cp .env.example .env
pip install -e ".[deepsearch]"
jiuwen-research "具身智能现在到哪一步了" --mode brief --engine deepsearch
```
